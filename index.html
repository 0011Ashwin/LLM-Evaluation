LLM Evaluation - How It Works

An interactive guide to understanding LLM and RAG evaluation

1. What is LLM Evaluation?

▼

LLM Evaluation is the process of measuring how well Large Language Models perform on specific tasks. It involves:

Quality Assessment

Evaluating accuracy, relevance, and helpfulness of model outputs

Comparison

Comparing different models or configurations to determine which performs best

Improvement

Identifying weaknesses and guiding model refinement

📊

Metrics

Quantitative measures like accuracy, BLEU, ROUGE, and custom scoring

🎯

Ground Truth

Reference answers used to compare against model outputs

🤖

Automated Grading

Using LLMs to evaluate other LLMs (LLM-as-a-Judge)

2. RAG Evaluation Process

▼

Retrieval-Augmented Generation (RAG) combines retrieval and generation. Evaluation focuses on both components:

Query
→
Retrieval
→
Generation
→
Evaluation

Retrieval Quality

Measure how well the system retrieves relevant documents

  • Context Relevance
  • Context Recall
  • Context Precision

Generation Quality

Assess the quality of the generated answer

  • Answer Relevance
  • Groundedness
  • Faithfulness

💡 Key Insight

Good RAG evaluation separates retrieval and generation to identify exactly where failures occur

3. Embeddings & Fallback Strategies

▼

Embeddings convert text to numerical vectors. Different strategies are used depending on available resources:

OpenAI Embeddings

When `OPENAI_API_KEY` is available, use high-quality OpenAI embeddings for better semantic understanding

Hash Embeddings (Fallback)

When OpenAI API is not available, fall back to deterministic local `HashEmbeddings` that:

  • Work offline without API calls
  • Produce consistent results
  • Allow the notebook to run without external credentials

🔑 Best Practice

Always have a fallback strategy so your evaluation pipeline can run in different environments

4. Grading with Structured Outputs

▼

Using LLMs to grade other LLMs requires careful prompt engineering and structured output formats:

Why Structured Outputs?

Ensure the grader returns parseable, consistent results that can be used programmatically

ChatGroq for Grading

Note: `langchain_groq` exports `ChatGroq`, not `GroqChat`. Use `ChatGroq` for structured evaluation outputs

Evaluation Criteria

Define clear rubrics for what constitutes a good answer:

  • Accuracy relative to ground truth
  • Completeness of coverage
  • Conciseness and clarity

5. Managing API Keys

▼

Securely managing API credentials is essential for reproducible evaluation:

.env File

Store keys in a `.env` file and load them at runtime:

  • LANGSMITH_API_KEY - For LangSmith tracing
  • GROQ_API_KEY - For Groq LLM access
  • OPENAI_API_KEY - Optional, for OpenAI embeddings

🔒 Security Note

Never commit `.env` files to version control. Add them to `.gitignore`
